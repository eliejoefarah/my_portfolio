AI Course Platform

An educational platform that uses Generative AI to produce personalized course content and quizzes — deployed and tested in a real classroom, with environmental sensor data from a Raspberry Pi feeding context into the generation pipeline.

ReactNode.jsOpenAI APIRaspberry PiREST API

The Problem

Generic educational content doesn't adapt to where students actually are — in comprehension, in attention, or in the physical environment. A lecture delivered in a hot, noisy room to distracted students is a different context than an engaged morning session. This project explored whether real-time environmental signals (temperature, noise level, CO₂) could be used alongside course material to produce content that was better matched to the actual classroom moment.

What I Built

Content Generation Pipeline

Course materials are chunked and stored as embeddings. When a student requests content or a quiz, the system retrieves the most relevant chunks via semantic search, injects them into a prompt with current sensor context, and generates a response through the OpenAI API. This keeps responses grounded in actual course material rather than hallucinating general knowledge.

screenshot: generated quiz or content card

Raspberry Pi Sensor Layer

A Raspberry Pi reads environmental sensors (temperature, humidity, noise, CO₂) at regular intervals and transmits readings to the backend via a REST API. The backend stores time-series readings and exposes aggregated context to the generation pipeline.

photo: Raspberry Pi sensor setup

Real Classroom Deployment

The platform was deployed during an actual course session, not just tested locally. Students interacted with it live, and interaction data was collected alongside sensor readings for post-session analysis.

photo: classroom deployment

One Interesting Decision

The most consequential decision was how to chunk course material for retrieval. Splitting by fixed token count breaks mid-concept, which causes the retriever to return fragments that make sense in isolation but mislead the generator. Instead, chunks follow structural boundaries — sections, paragraphs, and definition blocks — so each chunk carries a complete idea. This reduced incoherent quiz questions significantly in testing.

What I'd Do Differently

The sensor-to-prompt integration was fairly direct — high CO₂ → "simplify content," high noise → "use shorter sentences." A more principled approach would build a small evaluation set and measure whether these heuristics actually improved comprehension scores, rather than assuming they did. I'd also separate the sensor ingestion service from the main API so sensor failures don't affect content generation availability.
